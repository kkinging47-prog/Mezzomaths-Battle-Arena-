# Sunday BECE automatic expiry submission

From the 8 November 2026 Sunday paper onward, an expired Sunday session is finalised from the last answers saved to the server. Unanswered questions are incorrect, with the full 40-question denominator. The result includes an immutable review and auto-submission metadata. Its official time is the personal deadline, not the background worker execution time.

A Postgres cron job runs every minute even when the browser is closed. The server-only, SECURITY INVOKER finaliser locks pending rows with SKIP LOCKED, checks canonical stored session identity and question IDs, grades against the bank, and only updates incomplete sessions. It cannot alter already submitted results. Malformed/incomplete evidence is skipped rather than assigned an invented score. The rollout date prevents changing earlier weeks. School-lab and admin preview policies are unchanged.

The signed answer endpoint accepts expired proof only to retrieve/finalise this session's stored result. It ignores answers supplied after expiry. Early partial auto-submit, tampered signatures and cross-session lookups are rejected. A request that crosses the deadline while marking falls back to the stored snapshot. Anonymous and authenticated roles have no EXECUTE privilege on the finaliser; only the existing backend service role can invoke it.

The client submits automatically at expiry without confirmation or requiring all answers, locks the screen, displays the saved result and retries pending retrieval. Cached expired sessions offer result retrieval rather than a fresh attempt. Answer changes are sent immediately in serial order with keepalive, replacing the old 400ms debounce. Only progress received before the deadline is eligible; answers that remained offline cannot be accepted after time expires.

Validation: seven Sunday/report test files passed, including exact expiry, partial answers, unanswered questions, authoritative snapshots, tamper/early/lab rejection, repeat retrieval and real client no-confirmation flow. Production build passes. A rolled-back production dry run graded ten expired sessions with correct totals, scores and 3600-second duration; the scheduled worker then recovered those ten. One had no server-saved selections. Verified completed=40, active=5, expired pending=0 at 19:59 Ghana time, job success and restricted function privileges. Numbers are a point-in-time operational check, not fixed expectations.
